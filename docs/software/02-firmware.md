# 02 — Firmware: `libriscq` bare-metal library + build system

The on-core program ([README §3](README.md)): a C program cross-compiled to an ELF that runs *on a
core*, drives the hardware from the inside through the [CPU map](01-hardware-contract.md#2-cpu-map-per-core-data-bus-base-0x0),
and runs the experiment with no host in the loop during a shot. It is the single control path the SoC
supports on real hardware.

---

## 1. Purpose & scope

**In scope**

- A tiny freestanding runtime (`crt0.S`) and linker script (`riscq.ld`) for the 4 KiB core RAM.
- One canonical MMIO header `riscq.h` — addressing, bit-packing, and the control/readout/sleep/pulse
  accessors — **generated from the contract** so it cannot drift.
- A `Makefile` that builds one self-contained ELF per program with a stock RV32I clang.
- A handful of example programs (`pulse.c`, `readout.c`, `vna.c`).

**Out of scope**

- Physical-unit → integer-code conversion (Hz, radians, ns). That is **host-side**, in
  [`SocConfig`](01-hardware-contract.md#7-socconfig-the-python-object-and-the-source-of-truth) and the
  [program generator](04-pulse-and-program.md). The C side receives precomputed **codes**.
- Any libc / heap / interrupts / RTOS. The runtime is `set sp → call main → spin`.
- Envelope sample data — loaded host-side over AXI ([03-driver](03-driver.md)); firmware only writes the
  envelope **line index** into a pulse slot.

The division of labor is the whole point: **all arithmetic that needs floats happens on the host**; the
core has no FPU and only 4 KiB, so `riscq.h` stays thin — addressing + the `<<16` placement + the
blocking control/readout reads. A program is a short list of integer stores and a couple of halting
reads.

---

## 2. Where it lives

```
software/firmware/
  include/riscq.h     # canonical MMIO header — GENERATED by python/riscq/gen_header.py
  crt0.S              # _start: sp = 0x80001000; call main; j .
  riscq.ld            # flat image at 0x80000000, stack top 0x80001000
  Makefile            # clang rv32i, one ELF per .c
  examples/
    pulse.c           # play one gate pulse  (cross-checks vs sim/sw/pulse_sched.S)
    readout.c         # drive + demod + read one result
    vna.c             # frequency sweep
  build/              # *.elf + *.o (git-ignored)
```

`riscq.h` is a generated artifact. Its source of truth is `python/riscq/contract.py`; `gen_header.py`
emits the header so the C constants and the Python `SocConfig` are the same numbers. Hand-editing
`riscq.h` is the anti-pattern the RISC-Q reference fell into (three divergent `mmio.h` copies that
drifted). Until `gen_header.py` exists, a hand-written `riscq.h` is fine **as long as it is the only
copy**.

## 3. Design

### 3a. `crt0.S`

The entire runtime. Differs from the RISC-Q reference in one important way: the reference set
`sp = 0x1000`, assuming a separate low RAM. **Our SoC has exactly one RAM — 4 KiB at `0x80000000`** — so
the stack lives at the top of it and grows down into the same region as code/data.

```asm
    .section .text.init
    .globl _start
    .option norvc
_start:
    la   sp, _stack_top          # 0x80001000 (top of the 4 KiB RAM), grows down
    # zero .bss (cheap insurance — see note)
    la   t0, __bss_start
    la   t1, __bss_end
1:  bgeu t0, t1, 2f
    sw   x0, 0(t0)
    addi t0, t0, 4
    j    1b
2:  call main
    j    .                       # spin forever on return
```

- **`.bss` zeroing**: the host loader writes the whole ELF image into RAM, so initialized `.data` and
  `.rodata` are already live (no `.data` copy needed). `.bss` is *not* in the image, so a program that
  reads a zero-initialized global before writing it would see garbage. The zero loop is a few
  instructions — include it. (The reference omitted it and got away with it only because its examples
  never relied on zeroed globals.)
- **Stack**: 4 KiB is shared by code + data + stack. Keep call depth and locals small; see the §1
  ceiling note.

### 3b. `riscq.ld`

```ld
ENTRY(_start)
MEMORY { RAM (rwx) : ORIGIN = 0x80000000, LENGTH = 4K }
SECTIONS {
  .text   : { *(.text.init) *(.text*) }     > RAM
  .rodata : { *(.rodata*) }                 > RAM
  .data   : { *(.data*) }                   > RAM
  .bss    : { __bss_start = .; *(.bss*) *(COMMON) __bss_end = .; } > RAM
  _end = .;
  _stack_top = ORIGIN(RAM) + LENGTH(RAM);   /* 0x80001000 */
  /DISCARD/ : { *(.comment) *(.note*) *(.eh_frame*) }
}
```

A single flat region; no `gp`-relative model (hence `-mno-relax`, §3d). The linker will not warn if the
image overflows 4 KiB unless you assert it — add a `ASSERT(_end <= _stack_top - 256, "RAM overflow")`
guard so an oversized program fails loudly rather than corrupting the stack.

### 3c. `riscq.h` — the canonical header

Thin by construction. Three layers:

**(1) Bases & packing.** One macro applies the [`value<<16` rule](01-hardware-contract.md#3-field-encoding)
in exactly one place, resolving the reference's inconsistency (where `set_pulse_duration` shifted
internally but `amp`/`phase` expected pre-shifted args). Every 16-bit-field setter takes a raw code and
shifts; `startTime`/`fire` are written low.

```c
#define RF_BASE      0x10000u            /* gate=0x10000 readout=0x20000 demod=0x30000 decoder=0x40000 */
#define GATE   0u
#define RDRV   1u                        /* buffer selector → base = RF_BASE + buf*0x10000          */
#define mmio(a)        (*(volatile uint32_t*)(uintptr_t)(a))
#define pack16(code)   ((uint32_t)((code) & 0xffff) << 16)
```

**(2) Pulse-drive API** (gate + readout-drive buffers; offsets from
[§2b](01-hardware-contract.md#2b-rf-window-0x10000-0x50000--posted-write-only)):

```c
static inline void set_freq (unsigned buf, int code)            { mmio(RF_BASE+buf*0x10000+0x4)            = pack16(code); }
static inline void set_phase(unsigned buf, unsigned s, int code){ mmio(RF_BASE+buf*0x10000+(s+1)*0x10+0x0)= pack16(code); }
static inline void set_amp  (unsigned buf, unsigned s, int code){ mmio(RF_BASE+buf*0x10000+(s+1)*0x10+0x4)= pack16(code); }
static inline void set_env  (unsigned buf, unsigned s, int line){ mmio(RF_BASE+buf*0x10000+(s+1)*0x10+0x8)= pack16(line); }
static inline void set_dur  (unsigned buf, unsigned s, int n)   { mmio(RF_BASE+buf*0x10000+(s+1)*0x10+0xC)= pack16(n);    }
static inline void set_start_time(unsigned buf, uint32_t t)     { mmio(RF_BASE+buf*0x10000+0x4100)        = t;            } /* full 32-bit */
static inline void fire(unsigned buf, unsigned slot)            { mmio(RF_BASE+buf*0x10000+0x0)           = slot;         } /* index, low bits */
```

**(3) Demod / decoder / control / readout / time** (control block is plain 32-bit, no shift; the noted
reads **halt**):

```c
static inline void set_demod(int f, int p)  { mmio(0x30000) = pack16(f); mmio(0x30004) = pack16(p); }
static inline void arm_readout(uint32_t t, int dur){ mmio(0x44100)=t; mmio(0x40000)=pack16(dur); }   /* dur write clears+arms the result */

static inline uint32_t now(void)            { return mmio(0xbff8); }                  /* batch time */
static inline void     sleep_until(uint32_t t){ mmio(0x4000)=t; (void)mmio(0x4008); } /* timeCmp then halting waitTimeCmp */
static inline uint32_t from_host(void)      { return mmio(0x2000); }

static inline int  read_res (void) { return (int)mmio(0x4200); }   /* HALTS until integral settles; sign of I */
static inline int  read_real(void) { return (int)mmio(0x4204); }
static inline int  read_imag(void) { return (int)mmio(0x4208); }
```

Struct overlays (`pulse_table_t { int32 phase, amp, env, dur; }` cast onto `RF_BASE+buf*0x10000+0x10`)
are an optional convenience the generator can also emit; the flat setters above are sufficient and avoid
the reference's slot-0 aliasing trap (slot 0 overlaps `fire`/`freq`, so the API starts table entries at
`(slot+1)*0x10` — usable slots are `0…pulseNum-1` mapping to addresses `0x10`, `0x20`, …).

Table entries **persist** in the buffer, so the intended pattern is: load each distinct pulse once with
`set_freq`/`set_phase`/`set_amp`/`set_env`/`set_dur`, then launch each occurrence with just
`set_start_time(buf, t)` + `fire(buf, slot)` — two writes per launch. That pulse-table scheduling is what
[04-pulse-and-program](04-pulse-and-program.md) §3b generates.

### 3d. Build (`Makefile`)

```make
CC   = /config/build/riscv-install/bin/clang
ARCH = rv32i                         # rv32im when the core is built withMul
CFLAGS = -target riscv32 -march=$(ARCH) -mabi=ilp32 -mno-relax -nostdlib -static \
         -Os -ffreestanding -Iinclude
LDFLAGS = -Wl,-T,riscq.ld -Wl,-e,_start

build/%.elf: build/crt0.o build/%.o ; $(CC) $(CFLAGS) $(LDFLAGS) $^ -o $@
build/%.o:   examples/%.c            ; $(CC) $(CFLAGS) -c $< -o $@
build/crt0.o: crt0.S                 ; $(CC) $(CFLAGS) -c $< -o $@
```

- `-mno-relax` — no `gp`-relative relaxation (this freestanding image never sets `gp`).
- `-Os` — code size matters at 4 KiB.
- **One ELF per `.c`**, each linked with `crt0.o`; no shared lib (keeps each experiment trivially
  loadable, matching the host loader's whole-image copy).

**Toolchain note — stock clang is sufficient.** The RISC-Q reference core has *no* pipeline interlocks,
so its programs require a custom LLVM fork that pads every instruction with hazard NOPs. **Our core
handles hazards in hardware** — the standard `rv32ui`/`rv32um` test ELFs (stock-compiled, no NOP
padding) pass under RVLS lock-step in `RamOnFabricSim`. So we use stock clang and need no scheduling
pass. (We still call the clang at `/config/build/riscv-install/bin/clang` because it's present and
RV32-targeted; any RV32I-capable gcc/clang would also work.)

## 4. How it connects to other modules

- **[01-hardware-contract](01-hardware-contract.md)** — `riscq.h`'s addresses, the `<<16` packing, the
  `0x80001000` stack top, and the lead-time `now()→start_time→fire` pattern all come from there.
- **[04-pulse-and-program](04-pulse-and-program.md)** — the program generator emits the C
  body (a sequence of `set_*`/`fire`/`sleep_until`/`read_*` calls with integer codes from `SocConfig`)
  and invokes this `Makefile`. The C codegen target *is* this API.
- **[03-driver](03-driver.md)** — produces `build/*.elf`; the driver's ELF loader copies it into the
  core RAM region and releases reset. `read_*` results are read back by the host from the same RAM (a
  program leaves results at a known address) or consumed on-core.
- **`gen_header.py`** (in the [contract](01-hardware-contract.md#7-socconfig-the-python-object-and-the-source-of-truth)
  module) generates `include/riscq.h` from `contract.py`.

---

## 5. Extension points

- **`libriscq.a`** — if shared helpers grow (multi-pulse schedulers, calibration playback), build a
  static archive instead of per-file ELFs. Not needed for single-experiment programs.
- **Struct-overlay variant** of the pulse API (CMSIS-style `__OM`/`__IM` tags) for readability — emit
  alongside the flat setters.
- **RV32IM** path — flip `ARCH=rv32im` once `withMul` is enabled, for host-unavailable integer math on
  the core (still no float).
- **A second linker region** if a future core grows its RAM beyond 4 KiB — parameterize `LENGTH` from
  the contract's `memDepth`.

---

## 6. Minimal viable implementation

1. Write `crt0.S`, `riscq.ld`, `Makefile`, and a hand-written `include/riscq.h` (the §3c API) for the
   default config.
2. Write `examples/pulse.c`; **cross-check its emitted addresses against
   `src/riscq/soc/sim/sw/pulse_sched.S`** (`now()`→`0xbff8`, `set_start_time(GATE,…)`→`0x14100`,
   `set_freq`→`0x10004`, slot-0 fields→`0x10010/14/18/1C`, `fire`→`0x10000`).
3. Build it and confirm it loads and runs in `PulseTableSocCpuSim` (the existing CPU-in-the-loop sim
   that AXI-loads an ELF, releases reset, and observes the DAC) — that is the firmware sign-off.
4. Add `readout.c` (arm decoder → `read_res/real/imag`) and `vna.c` (sweep with `sleep_until` between
   points).
5. Only then write `gen_header.py` and switch `riscq.h` to generated, diffing the generated addresses
   against the hand-written one to prove equivalence.

## 7. Open questions

- **Result return path.** When the host wants the readout back, the program must store
  `read_real()/read_imag()` to a fixed RAM address for the host to read over AXI (the reference used
  `0x80000400`). Pick and document one scratch address (or a small result-ring) as part of the contract
  so [03-driver](03-driver.md) knows where to look.
- **Stack-overflow safety.** 4 KiB is tight; decide whether the `ASSERT` guard + a documented max
  call-depth is enough, or whether a tiny stack-canary check is worth the bytes.
- **`gen_header.py` ownership.** Confirm it lives with `contract.py` (Python module) rather than as a
  standalone script, so the header regenerates whenever the contract changes.
